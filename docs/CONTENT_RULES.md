# 内容采集与运营规则

从根 [AGENTS.md](../AGENTS.md) 拆出的内容采集、来源、批次与页面规则，原文保留、效力不变（强规则）。任何内容采集、核验、入库或发布前必须完整读取本文件；代码维护不需要。

## 讯息采集硬规则（用户于2026-10-11明确指定）

本规则适用于本项目所有LLM、Agent、内容运营与定时任务的X采集；包括「美股讯息」「具体人物」「具体个股」「AI板块」及以后新增的X信息页面（「加密」暂时停用）。宏观/财报、CNN情绪、VIX、Nature/Science论文及反直觉小知识各有明确非X例外，不得把例外扩展成新闻第三路径。宏观为低频官方日历。

1. **第一路径：Grok Bot「X+github」。** 本机执行器按侧边栏Tab逐批使用，只发送本批需要的公开问题，不把全站清单塞进同一会话。确认Bot实际可用；额度耗尽、未发送草稿或界面不可用等阻塞时保留用户内容，不反复重试，在审计记录原因。采集结果与页面发布仍由本机单一路径处理。
2. **唯一备用路径：已登录的 Grok 网页版（https://grok.com），使用 Expert 专家模式。** Bot不可用或完成后结果存在明确覆盖／证据缺口时，网页补查对应对象并记录切换原因。上一路同一对象、窗口及阶段仍在运行或无法确认是否停止时不启动重复查询；只有已完成、明确失败或确认停止后才定点补缺口。额度用尽不循环重试或切换账户。每个新会话发送前确认界面已选择Expert，记录实际模型标签及确认时间；不要求显示具体版本，不静默改用Auto/Fast。已满足要求的Bot结果不必重复检索。
3. **仅允许以上两条路径。** 不得改用直接浏览X、X API、xreach、普通网页搜索、其他采集器、其他AI信息服务或模型记忆补采。不得读取应用内部数据库、凭证或调用未公开接口绕过正常界面。仓库中的旧X API脚本和旧文档不构成使用许可。
4. 两条路径均失败时，保留旧内容、明确报告失败原因；不得自行寻找第三条路径，也不得把失败写成“暂无新增”。
5. 保留Grok返回的原帖链接、作者、准确时间、正文和覆盖缺口。Grok回答是采集器转述，不能标为本模型已独立直读X原帖；缺失或截断内容不得补写。
6. 向外部检索仅发送本次需要的公开问题，不发送个人资料、账户数据、仓库外私有知识库或整份项目知识库、历史及无关契约；项目知识由本机按下一条提取必要内容。不发社交帖、不私信、不点赞、不关注、不交易。
7. **检索必须加载项目知识。** 本地执行器在每个X批次前读取 `config/research-guidance.json` 指向的项目知识库、Grok采集SOP及该Tab契约；事实流以半导体、电力、AI落地为优先级生成发现、追源、反证问题。独立个股热点只发送其单股简短提示词，不将知识库、事实门槛或JSON契约附加到检索请求。不得另行读取或发送用户私有知识库、账户资料与凭证。

用户明确修改之前，不得以提速、自动化、技能建议或工具不可用为由例外。共享技能若描述其他采集方式，本项目仍按上述用户规则执行。

## 来源例外：Nature / Science 论文

用户授权每日学习两刊正刊选读，偏健康、生活、统计与反直觉，不主推技术。严格按[论文SOP](./JOURNAL_PAPERS.md)：本机优先查期刊、Crossref/PubMed和作者/机构合法公开版本，不必先调用Grok。只用于论文，不放宽X采集；准确标记摘要/节选/正文、发表与选读日期，查询更正与复现，无合格内容不凑数。

「反直觉小知识」优先复用合格证据；需要新增检索时由本机优先查原始论文或官方统计/教育资料。按[小知识SOP](./COUNTERINTUITIVE_KNOWLEDGE.md)保存来源与边界，不扩大新闻采集权限、不用模型记忆代替事实核验。


## 检索前先定清单（用户于2026-10-12明确指定，适用于所有采集）

任何信息检索（美股简报、人物页、个股页、AI板块、加密页、财报结果、来源核验等）开始前，执行器必须先写出本次的**检索清单**：时间窗、要覆盖的对象（每位人物 / 每个美股个股 / AI实验室或政策主题 / 加密板块或标的 / 每个主题 / 每家待评价公司）、每项要回答的问题和计划用的查询。检索完成后逐项对照清单，标明「已覆盖 / 无结果 / 证据不足」，写入审计记录。清单里有一项没处理完，就不得校验推送。不能边搜边定范围，也不能等用户发现遗漏后再补。

清单必须按侧边栏Tab分别建立和关闭。一个Tab的候选、数量目标或失败原因不能拿去填另一个Tab；人物、个股和AI页再按各自顶部Tab建立子清单，但仍在所属侧边栏批次内汇总。

## 重要内容必须入库（用户于2026-10-12明确指定）

凡涉及本项目的重要产品规则、真源决策、筛选标准、页面行为或长期约定，必须写入仓库（优先 `AGENTS.md` / `CONTEXT.md` / `docs/` / `config/`），不得只留在对话或执行器记忆里。仓库文档优先于历史对话。财报日历的筛选核心见 [`docs/EARNINGS_CALENDAR.md`](./EARNINGS_CALENDAR.md)。

## 人名原文与人物简介（用户2026-10-13明确指定）

适用于所有讯息卡片（美股讯息、人物、个股、AI及以后新增页面；加密已暂停）：人名保留原文写法（如 Satya Nadella、Donald Trump），不写中文音译（纳德拉、特朗普等）；每张卡片的 `people` 列出提到的人物及 ≤15 字简介，来自 `config/person-registry.json`。登记表外的新人物：先在登记表新增原文名、经核实的简介、中文音译别名和匹配词，再发布。原帖摘录 `excerpt`、原始帖子正文与已记录的检索问题 `queries` 属于证据/历史记录，不改写。发布流程（`prepareBrief`、各分页 `prepare*Intelligence`）遇到人名音译直接失败，并按登记表自动写入 `people`；`npm run check` 对当前及归档卡片同样失败。旧数据用 `node scripts/normalize-person-names.js` 幂等迁移。人物页顶部 Tab 名（马斯克/黄仁勋/特朗普）属于栏目配置标签，暂保留，用户要求时再改。

## 人物页热度补位（用户2026-10-13明确指定）

人物页所有 Tab 新增区目标 5 条：现有价值规则优先，不足用本 Tab 来源热度最高帖子补足（标「热度动态」），无规则条目时收热度最高 3 条；互动数只记 X 工具返回值。规则与解释见 [PEOPLE_INTELLIGENCE_ROADMAP](./PEOPLE_INTELLIGENCE_ROADMAP.md)「收录与热度补位」，配置 `config/people-intelligence.json` 的 `selectionPolicy`。

无高价值不等于无动态。新增区为空必须保存`selectionChecks`中的实际补位查询与无可收录帖原因；发布程序拒绝未做补位检查的空结果。政策追源对已授权候选可取直接相关政府主管部门的X原帖，热度来源仍按Tab配置；拆开已确认事实和未确认细节，不能因金额等单一字段缺证据而丢弃官方已确认的其余事实。

## 北京时间批次与周末消息（用户2026-10-12最新澄清）

按[采集入口](./INCREMENTAL_COLLECTION.md)，事实和个股热点对象严格从各自上次成功截止接续，手动与定时共用`data/collection-progress.json`；事实不每轮宽搜24小时，不因无高价值新增重置整窗。独立个股热点按本股增量窗取浏览量榜，不混旧浏览量。失败只补失败对象；查询完成/无结果与卡片数量、部署成功分开。真实结果落盘后才更新记录，不能把提示词或计划当采集证据。事实新候选追源/反证，旧证据无变化复用；无候选后两阶段无需执行。

展示按[北京时间批次规则](./TRADING_DAY_READING.md)累计保留，08:00早报到20:00仍可读；事实流的24h/7天/30天是阅读范围，不是重复检索范围，个股热点按独立进度及专门契约展示。周一汇总已入库的完整周末事实，只搜余下增量，不等待美国开盘。三期快照与持久池独立；失败不清空，已展示不等于已读，更正保留原卡及依据。

旧 `config/us-market-calendar.json` 保留供历史追溯，不再驱动本栏目收录与保留。财报/宏观自己的官方时间规则不因此改变，也不扩大X来源权限。每次内容发布同时提交、核验 `data/reading-board.json`。

## 财报日历刷新与结果评分

详见 [`docs/EARNINGS_CALENDAR.md`](./EARNINGS_CALENDAR.md)。摘要：日常讯息更新可轻量刷新日历；**结果核验只查「已知已发财报且尚未评价」的公司**，不做全表重复劳动。每次更新拉取日历后，必须先处理 `pendingReview`（已过披露日未评价的公司）：当场查结果并评分，清空后才可校验推送。评分 0～100（符合预期 60～70，超预期 70～90，远超预期 90+，不及预期 &lt;60）。

## 页面入口

每日更新的日期选择和每日快照最多保留最近三期，一个北京时间日期为一期，同日多轮累计。按[每日更新契约](./DAILY_UPDATES.md)维护，不能在后续发布时恢复为长日期列表；原始消息和采集凭证保留。

侧栏首项[每日更新](./DAILY_UPDATES.md)是四个X来源栏目的只读聚合，不创建第五个X采集批次。全部配置股票执行[独立X热点](./TICKER_INTELLIGENCE.md)：每股独立会话，优先Bot、网页备用用Expert；只用股票代码关键词＋该股上次成功截止至本次实际截止，按浏览量取前五，不加主题、账号、官方身份、广告或观点过滤。GOOG同时覆盖GOOGL；短代码按配置用证券标记消歧。短提示词真源`scripts/lib/ticker-hotspot-prompt.js`，`collection:plan`列出逐股问题；Grok自行检索排序，读取后本机整理字段，不混发事实任务/知识库/JSON契约。热点成功后采用本次增量窗排名，不混排旧浏览量；事实与热点两流进度独立。缺views不编排名，已知遗漏或错误须针对性核对，明确缺口，不声称全X前五；标非官方、不挤占价值配额，人物页规则不变。

“板块空头”不展示、采集或部署，旧链接跳转美股讯息；“加密”暂时停用。侧栏“宏观大事”紧挨“财报日历”上方，完整顺序及页面行为见DESIGN_SYSTEM。

## 来源例外：财报日历与财报结果（用户于2026-10-12确认）

“只走 Grok App / Grok 网页版”的硬规则适用于 **X 讯息采集**（美股讯息、具体人物、具体个股、AI板块；加密已暂时停用）。AI与美股个股分页采集，不得混入 `tickers` 任务。财报模块是明确例外：

1. 财报日历：`npm run fetch:earnings` 直接请求 Nasdaq 公开日历接口（`config/earnings-calendar.json` 的 `source.endpoint`）。单日失败按指数退避重试；仍失败则沿用上次数据并标 `stale`，不中断其余日期。
2. 财报结果评分：以公司官方披露为准（新闻稿、8-K/10-Q、管理层讲稿），一致预期可引用公开财经页面；X 只作补充线索。每项评分附来源链接。无法核实时标 `status: "unknown"` 并写明原因，不得编造分数。
3. `pendingReview` 非空时 `fetch:earnings` 以退出码 2 结束，`npm run check` 对“已过披露日仍 unreviewed”的条目直接失败。

## 检索记录与检索前清单

`data/collection-progress.json`为逐对象进度真源，用`collection:progress record`推进；旧`search-coverage.json`保留审计，不再用整窗partial阻塞所有对象。新载荷附`collectionMode: incremental-v1`与对象窗口，新闻事件附`collectionUnit`；仍保存两轮清单、候选和落选原因，不降低事实契约。

## 已知数据缺口（如实记录，不补写）

- 2026-10-12 09:00 期（schemaVersion 1）上线 3 条焦点 + 4 条洞察（partial）。当期对话里两轮检索曾交付 10 条和 12 条候选，但归档时未保存候选到入选的映射，落选理由只部分记在 `excludedCandidates`。该期归档已冻结，不回填内容；自 schemaVersion 2 起强制保存 `candidates`。
- X 讯息采集完全依赖 Grok App/网页版与 X 的可用性（限流、App 授权、浏览器可用性）。这是外部依赖，失败时按规则发布失败记录，不改走其他路径。

- UI 禁止任何文字截断（省略号、line-clamp、裁切、JS 截字）；详见 docs/DESIGN_SYSTEM.md「禁止截断」。
