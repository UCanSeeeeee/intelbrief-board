## 为什么产生重复劳动

1. **查询时间窗没有承接。** 手动新闻窗口是10月17日19:43至18日19:43；紧接的定时新闻、个股及AI审计仍明确回查截至20:30的24小时。两次截止只差47分钟，新闻窗口重叠23小时13分钟。阅读范围24小时被混作每次搜索范围，手动结果也未推进定时进度。
2. **固定阶段的启动成本。** 四个X侧栏各独立串行执行发现、追源、反证，美股发现还分两轮；这种隔离有质量目的，但即使个股、AI最终没有合格新增也走了后续环节。定时四批记录22、25、23、23条queries，共93条审计查询条目；它们不等于93次独立外部请求，不能用这个数推算每次调用延迟。
3. **旧消息重复复核而新增很少。** 定时美股记录1条新焦点、3条复核焦点、1条复核洞察；人物1条热度动态；个股、AI零合格新增。质量闸门有用，但没有新事实的旧卡每轮重查，成本没有随新增量下降。不能把“查过但落选”一律算浪费，也不能为提速放宽准入。
4. **本地检查与顺带修补是次要成本。** 20:30日志记录了测试、构建及既有简介缺项修复；旧保存的任务要求与当前“不做本地验证”口径冲突，本次已清理。该阶段1分57秒包括多种工作，不能准确拆分。重复加载大段规范可能另有开销，但旧日志没有独立计时，属于待测机制而非已测分钟数。
