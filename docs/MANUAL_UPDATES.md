## 接通

### 本地调试模式

运行 `npm run dev:updates` 同时启动本地网站、持久化任务队列和执行器，打开 http://localhost:8787 。本机访问免登录，该模式仅用于调试执行器，数据只写入本机工作区；调试得到的数据若要保留，必须按 AGENTS.md 提交并推送。任务、断点和本机密钥位于 `~/.local/share/intelbrief-updates/local/`，与云端配置隔离；本地免登录仅在显式本地标记且主机名为回环地址时生效。停止命令后网页/执行器停止，重开命令恢复持久化记录。

### 云端接入

1. `npm ci`，然后 `npx wrangler login` 完成 Cloudflare 登录。
2. `npm run updates:setup`：创建或复用 `intelbrief-updates` D1，初始化表，配置 Pages 的 `UPDATES_DB` 绑定与两个密钥。脚本幂等复用本机配置，不打印密钥。
3. 在现有 Cloudflare Pages 项目确认构建命令为 `npm run build`、输出目录为 `dist`，部署本次代码。`wrangler.toml` 的 D1 绑定和输出目录作为部署配置；不得继续使用空构建命令。
4. `npm run deploy` 或推送 `master` 触发既有 Git 集成；确认 `/api/updates` 返回“登录后可更新内容”，而不是“更新服务尚未接通”。
5. `npm run updates:start` 启动本机执行器。它每15秒领取已提交任务，不自行扫描X、不新增定时简报。关闭此进程/电脑睡眠会显示执行端离线。常驻启动方式需在上线时落实，不把交互终端启动描述成开机自启。
6. 本机 `~/.local/share/intelbrief-updates/config.json` 的 `adminKey` 用于网站更新面板登录。文件权限600、目录700；不要粘贴到聊天、提交仓库或放进前端。网页使用30天的安全HttpOnly会话Cookie，不在localStorage保存密钥。
7. 先执行单页，再执行全部更新，抽查原帖证据、线上归档、失败和无新增状态，确认真实链路后再标记上线。

页面只接收固定页面标识，不能提交任意提示词或Shell命令。执行端使用独立密钥领取任务；它启动已登录的 `codex exec`，继承本机模型配置，限制为只读研究，再由普通Node程序校验与发布。采集来源统一遵守 [AGENTS.md](../AGENTS.md)：本机Grok Bot App固定使用「X+github」主执行Bot，失败才用Grok网页版；旧「推特信息获取」只保留历史，不再使用，也没有第三条路径。执行器关闭普通网页搜索，拒收其他获取路径的结果。登录或UI权限不可用必须如实显示，不能绕过。

执行器生成每个采集提示时，会读取 `config/research-guidance.json` 并把项目知识库与 Grok 采集 SOP 注入执行上下文。Grok 只接收由这些材料生成的公开检索问题，不接收知识库全文。美股讯息、具体人物、具体个股与加密共用同一套追源、反证和降噪闸门（加密主题优先级见 crypto 配置），避免不同触发方式产生两套标准。

## 归档与发布

- 手动简报以受理时间为信息截止，文件为 `manual-<任务编号>.json`；定时整点归档不变，均不可覆盖。定时窗口只参考以前的定时期次，手动更新不移动定时采集起点。
- 人物按账号记录检查时间。仅完整检查成功的账号推进时间，部分失败保留原断点；原帖按ID去重，保留完整人物时间线。人物更新不修改美股简报。
- 个股按 Tab 报告覆盖；schema 与人物情报事件库对齐。加密任务（page=`crypto`）独立写入 `data/crypto-intelligence.json`，不得写入 tickers。Brew 须按合约检索但只保存 X 证据。
- D1限制每页一个活动任务、全局一个执行中的任务。重复点击复用任务，全部更新补上未提交页面。有效租约每20秒续期，过期执行端不能再写任务结果。
- 每个任务使用独立本机检出目录，只提交明确的数据文件。普通远端变更尝试rebase，冲突时保留证据并停止，不强推、不重置用户目录。
- 校验后保存发布断点。推送后逐个核对线上受影响JSON与本机内容；未确认发布不显示完成。发布失败重试复用断点，不重新采集。已发布的失败简报重试新建手动期次，保留失败历史。
- 无新增也保存真实检查记录；全部人物采集失败保留原数据，不冒充无新增。部分完成显示缺额/失败账号。
