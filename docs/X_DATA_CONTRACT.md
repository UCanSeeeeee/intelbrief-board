# X 数据契约与可信度边界

最后更新：2026-10-11（Asia/Shanghai）

## 系统边界

- 只采集 X/Twitter 帖子正文、作者、时间、原帖链接、引用关系、媒体元数据和抓取时可见互动量。
- 不把非 X 网页正文混入情报库。帖子包含外链时只保存链接元数据，不自动把外链内容当作已核验事实。
- 不发帖、不点赞、不转发、不关注、不私信，不执行交易。
- 没有真实原帖时，页面显示空状态；禁止用占位新闻替代。

## 允许的输入

来源硬规则统一见 [AGENTS.md](../AGENTS.md)：先本机Grok Bot App，失败时才使用Grok网页版。不得从X API、直访X或其他采集器取得新数据。历史脚本与字段不构成例外。

上述两条路径的结构化结果可使用 `npm run import:x -- path/to/export.json` 导入；注明实际获取路径与Grok返回、未独立直读状态。

导入文件可以是数组，也可以是 `{ "posts": [...] }`。最低要求：

```json
{
  "posts": [
    {
      "url": "https://x.com/OpenAI/status/1234567890",
      "author": { "username": "OpenAI", "name": "OpenAI" },
      "createdAt": "2026-10-11T08:00:00Z",
      "text": "原帖完整文本",
      "category": "ai",
      "topics": ["OpenAI", "AI"]
    }
  ]
}
```

导入器会从 URL 提取 status ID，并按 ID 去重。缺少原帖链接、准确时间或完整正文时拒绝导入，不猜测缺失内容。

## 可信度评分

总分为 `作者分 × 40% + 主张分 × 60%`，结果始终标为 `auto-provisional`（自动初评）。

作者分来自 `sources/x-sources.json` 的人工登记：

- `primary`：机构或组织的一手账号
- `direct`：具名当事人
- `established`：有明确编辑责任的成熟来源
- `specialist`：可识别的垂直研究者
- `monitored`：观察中、尚未充分校准
- `unknown`：未进入来源表

主张分由以下项目组成：

- 直接程度：0–30
- 可追溯证据：0–25
- 独立 X 帖印证：0–25
- 具体性：0–10
- 记录完整性：0–10
- 传闻、反证、原帖失效、只有截图：扣分

独立印证只接受人工写入 `assessment.independentSupportPostIds` 的帖子 ID；系统会检查支持帖作者必须不同。相反证据写入 `assessment.contradictionPostIds`。

## 解释限制

- 评分不是“为真的概率”。
- 官方账号只对“该账号确实这样宣布”有较强证明力，不自动证明营销性或预测性主张为真。
- 蓝标、粉丝量、点赞量和转发量不加分。
- 多个账号复读同一传闻不自动算独立印证。
- 分数适合排序核验优先级，不应直接映射为买卖信号。
