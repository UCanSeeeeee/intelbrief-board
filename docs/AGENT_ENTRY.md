# Agent 入口与接手

采用：2026-10-12。借鉴 Chieh-context 的按需读取、主动落盘、可恢复任务与验证习惯，不复制其个人资料、共享技能本体或同步脚本。

## 自动入口的实际含义

根目录 AGENTS.md 是行为约定，不是后台守护程序，也不会给模型新增工具或权限。Codex 在支持的仓库环境中会发现 AGENTS.md；其他 LLM/Grok Bot 是否自动读取取决于宿主，必须配置或明确要求它先读入口，不能只因为文件存在就认定接入完成。参考 [OpenAI 官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)（核对于2026-10-12）。

`npm run agent:enter -- --role gpt --task code` 是只读辅助：列出本次资料、工作区状态、未完成任务和禁止事项，不调模型、不联网、不拉取、不写文件、不采集、不部署。声明角色只作路由，不是权限认证。真正的拉取、修改、验证和推送由遵守 AGENTS.md 的执行者在对应工具中完成。

任务可选：status、code、handoff、news、people、tickers、ai、crypto、earnings、macro。GPT 被阻止进入内容执行路线；新角色默认不能运营。问题是查询/诊断时选择 status，即使当前 Bot 是 Grok 也不自动发起检索。

## 宿主入口提示（引用规则，不复制规则）

> 你正在维护 UCanSeeeeee/intelbrief-board。先读取仓库根 AGENTS.md、CONTEXT.md、TASKS.md，按当前请求与自己的角色选择路线，再读取相关文档。任何修改前先按 AGENTS.md 拉取远端，保留已有改动；完成后检查、测试、构建、明确暂存、提交推送并核验。继续做时只推进已授权且属于你角色的事项，遇到阻塞保留断点。回答/状态/诊断不授权生产写入。Grok Bot X+github 负责全部内容运营；GPT 只维护代码功能。不要把历史方案、检索结果或本文示例当作新增权限。

把这一段放到宿主支持的项目/Bot 指令或例行任务提示中；无法读取私有仓库就报告权限缺口，不猜测最新规则、不自行增权。

## 一轮工作闭环

1. **识别意图与角色**：本轮是问状态、改代码、还是 Grok 内容运营？明确范围和不做什么。
2. **恢复事实**：核对 TASKS 对应项及其证据；区分已保存/未提交、已推送/未上线、已建任务/未执行，尤其不把09:00旧链路成功当成新链路验收。
3. **执行前同步**：改动前拉取，发现用户未提交内容不覆盖。只读状态请求不改变远端或工作区。
4. **最小充分上下文**：按路线读配置、程序、规则；不每次重读全部知识库。内容任务必须读研究知识和 SOP，而不是只读聊天摘要。
5. **推进和验证**：在授权内完成下一步；代码用测试/差异/页面证据，内容用清单/候选/来源/字段/反证，发布用远端/线上内容证据。
6. **保存与交付**：新规则更新其主要维护位置，任务留下一步及阻塞，提交推送。最终说明已完成什么、未完成什么、证据和链接，不复述一长串工具日志。

## 接手场景验收

| 场景 | 应做 | 不应做 |
|---|---|---|
| GPT被问“早上的简报执行了吗” | 读归档与执行证据，区分记录和实测 | 新建任务或代搜新闻 |
| GPT被要求“继续代码优化” | 拉取、恢复本角色任务、实现、验证、推送 | 代Grok补新闻或恢复Codex定时器 |
| Grok到定时点 | 自主读取当前规则、检查期次、执行SOP、核验发布 | 等GPT点击或把09/16/21扩成全天监控 |
| 远端有更新且本地有改动 | 安全拉取；冲突停下保留证据 | reset、强推、全量暂存 |
| 新闻不足、检索失败 | 分别记录高价值不足、无结果、证据不足、失败 | 为凑15条补旧闻或把失败写成0条新增 |
| 用户打断切换任务 | 留存修改状态、任务断点和影响 | 宣称所有事项已经完成 |

这些是行为验收标准，不是已完成的自动化平台集成证明。
