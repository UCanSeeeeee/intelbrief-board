# 财报日历

采用日期：2026-10-12。

## 功能核心（用户于 2026-10-12 明确指定）

本页不是「按市值扫大票」或「只显示死名单」。筛选核心是：

1. **必看主题池**：AI 半导体、电力、软件；老牛股 / 质量股（例如 UNH）；新兴科技。
2. **自主判断**：不在上述主题里的公司，执行器仍须按项目研究优先级（半导体 → 电力 → AI 落地，以及宏观/产业传导）自行判断是否值得进入当周日历，说明理由；不得因为不在固定名单就一律丢弃。
3. **固定名单不是系统**：`alwaysInclude` 等配置只是辅助种子，不能替代主题池 + 自主判断。

用户明确修改之前，不得退回「仅市值门槛」或「仅观察名单」模式。

## 数据源

- **稳定主源**：Nasdaq 公开日历 `https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`
- 请求需浏览器 `User-Agent`，以及 `Origin` / `Referer` 指向 `https://www.nasdaq.com`
- X 博主或券商周报只可作可选交叉核对，**不作系统真源**
- 财报**结果**（用户于 2026-10-12 明确指定）：以公司官方披露为主源（IR 新闻稿、8-K/10-Q、管理层讲稿），一致预期可引用公开财经页面；X 只作补充线索（市场反应、管理层表态），不作结果真源。每项评分须附来源链接。日历日期本身以 Nasdaq 为准

## 刷新与结果回看（用户于 2026-10-12 明确指定）

1. **挂在每日讯息运营批次上**：在北京时间周一至周五 08:00 / 20:00、周六 08:00、周日 20:00 做美股讯息更新时，顺带刷新上周 / 本周 / 下周 Nasdaq 日历，并检查已过披露日的重点股是否**已经有财报结果**；有结果则按下方标准评分总结。不为日历单独叠一套复杂独立刷新流程。
2. **周末休市**：美股周六、日不开盘；**周一**更新必须把上周六、日相关讯息一并纳入（见 `docs/STOCK_BRIEF.md`），日历结果回看同样覆盖周末已披露内容。
3. 经授权的临时内容任务可刷新日历与结果；X采集仍共用项目逐对象进度，不覆盖已有定时期次。网页不提供更新入口，暂停的Bot不因临时任务自动恢复。

实现上：日历日期拉取可走 Nasdaq HTTP；结果评价按 AGENTS.md 的财报来源例外，以公司官方披露为准，公开一致预期作比较，X仅作补充。内容由本机运营的独立「财报日历」批次处理，不与其他Tab混采。

## 结果回看范围（用户于 2026-10-12 明确指定）

日常讯息更新时，**不要对整周日历做重复的结果检索**。只处理同时满足以下条件的公司：

1. 已知已经发布财报（或已确认披露发生）；
2. 项目内尚无有效的结果评价（未查过 / 仍为 unknown 且当时证据不足后出现新披露，可再查一次）。

已评过分且无新材料的，跳过。日历日期表可轻量刷新，但结果核验必须增量、可审计。

## 结果评分标准（用户于 2026-10-12 明确指定）

执行器对每家已披露公司自行总结档位，并给 **0～100** 分：

| 档位 | 分数指引 | 含义 |
|------|----------|------|
| 不及预期 | &lt; 60 | 关键指标或指引明显弱于一致预期 / 需下调判断 |
| 符合预期 | 60～70 | 大致符合一致预期，无重大正负意外 |
| 超预期 | 70～90 | 明显好于预期，或指引上修但未到极端 |
| 远超预期 | 90+ | 大幅好于预期且质量高（增长/利润/指引共振） |

要求：

- 分数与档位一致；写清依据（EPS/营收/指引/质量），区分事实与判断。
- 信息不足时标 `unknown` / 暂不给分，不得编造。
- 评价服务研究阅读，**不是交易指令**。

## 生成本地数据

```bash
npm run fetch:earnings
```

写入 `data/earnings-calendar.json`（schema v2）：`weeks` 含 `last` / `current` / `next` 三周，按北京时间定本周（周末则以下周一为本周）。入选逻辑：先命中 `config/earnings-calendar.json` 的主题池，其余超大市值（`autonomousMinMarketCapUsd`）作为自主判断候选并写明理由；每项保留 `selectionReason` 与 `result`。重新拉取会保留已有评分。

## 拉取即回看（用户于 2026-10-12 明确指定）

每次定时讯息运营或 Grok Bot 临时内容任务，执行器按以下顺序做，不得跳过：

1. 运行 `npm run fetch:earnings`；脚本输出并写入 `pendingReview`：披露日早于北京时间今天、且结果仍为 `unreviewed` 的重点公司。
2. **当场**逐家查询实际结果（EPS、营收与一致预期对比，以及指引），按评分标准写入 `result`；证据不足就标 `unknown` 并写明原因。
3. `pendingReview` 清空后才进入校验和推送。

不能先上线、等到用户发现或校验拦住再补查。

## 上线拦截（2026-10-12 起，最后一道保险）

`npm run check` 会拦住：披露日早于北京时间今天、但 `result.status` 仍为 `unreviewed` 的重点公司。必须先评分，或证据不足时标 `unknown` 并写明原因，才能推送。已评分项须有 0～100 分、与分数一致的档位、总结和来源链接。

## 页面

侧栏位置以 CONTEXT.md 的八页顺序为准，财报日历为 `earnings.html`。页内顶部 Tab：**上周 / 本周 / 下周**，默认打开本周。构建时随 `npm run build` 进入 `dist`。

## 拉取健壮性与筛选（2026-10-12 修订）

- 每天的日历请求失败时按指数退避重试（`source.retries`，默认 3 次）；仍失败则沿用上次该日数据并标 `stale`，页面显示“可能过时”，其余日期照常更新。
- 代码统一规范为 `BRK.B` 格式（`BRK-B` 自动转换），主题池内重复代码已去重。
- 主题命中不设市值门槛；非主题公司仅当市值 ≥ `autonomousMinMarketCapUsd` 时自主入选（已删除未生效的 `minMarketCapUsd`）。
- 每日超过 `maxPerDay` 的公司写入当日 `truncated`，控制台与页面都会提示，不再静默丢弃。
- `pendingReview` 非空时脚本退出码为 2，`npm run check` 同时拦截已过披露日仍未评价的条目。
