# 美股定时简报：执行与数据约定

采用日期：2026-10-11。用户确认的筛选框架为「多学科认知和夜雨知识库」。本文是简报流程的主要维护位置；频率和条数以 `config/stock-brief.json` 为机器配置。

手动更新新增独立期次，受理时间作为信息截止；不会改变本文件规定的定时期次与定时采集窗口。任务接入、上线状态与发布重试规则见 [手动更新](MANUAL_UPDATES.md)。云端验收前维持本文件现有定时流程，验收后将既有调度切换到同一任务队列。

## 产品规则

- 每天北京时间 09:00、16:00、21:00 **启动**采集，包括周末；核验完发布，不承诺整点瞬间交付，也不在其余时段持续扫描。
- **周末休市与周一补扫（用户于2026-10-12明确指定）**：美股周六、周日不开盘。周一各次更新必须把**上周六、周日**窗口内的 X 讯息一并纳入检索与筛选，不得因休市跳过周末信息；`marketContext` 标明休市背景。财报日历在每日讯息更新时顺带回看本周已披露结果并评分，不为日历单独叠一套复杂刷新流程。
- **展示窗口与检索窗口分离（用户于2026-10-12通话明确指定）**：展示给用户的内容必须覆盖从本期信息截止点往前完整 **24 小时**（例如今天 09:00 启动的期次，展示窗口为昨天 09:00 至今天 09:00），即使实际检索是从最近一个成功定时期次的截止时间开始（例如昨晚 21:00 至今天 09:00 的 12 小时）。具体检索范围由执行器自行决定：可以只检索尚未覆盖的时段，避免重复检索；已检索过的时间段应在本地存储记录（记录每个时间段做过哪些检索），以便去重。也就是说：检索可以按需分段，但展示必须是完整的 24 小时窗口。周一补扫不得因分段检索而漏掉。
- 第一组 5 件事：本期检索范围内最受市场关注、最影响美股整体方向的独立事件。以影响广度、重要性、时效、相对预期变化排序，说明关注依据；没有横向数据就不声称客观全网前五。
- 第二组另外 10 件事：以多学科认知与夜雨知识库筛选，说明「事件 → 中间变量 → 企业利润/折现率/资金结构 → 美股影响」以及反向条件。至少连接两个学科；不能只贴知识卡标签。
- 两组按事件去重，同一发布/同源转述不拆成多个名额。个股议题沿用 AI 相关大中型公司的既有范围；宏观与整体市场事件不受个股池限制。不产出交易指令。
- 只从 X 获取证据。外链、Grok 的概述或知识库里的旧观点不是当期已证实事实。区别已直读原帖与采集器转述；未能查清的时间、原文、身份不得猜测。没有准确发帖时间与 URL 的候选不收录。
- 满额才标为完整；证据不足保留实际条目并说明缺额，全部失败发布失败记录。周末标明休市背景，不把前一收盘价当实时行情。延续事件必须说明为何仍重要，不用旧闻冒充新增。
- 前台期次区只保留期次选择器；目录与归档最多保存最近三期，写入第四期时自动移除最旧一期。
- 可信度与市场影响排序分开。自动分数不是概率；当前来源规则尚未经结果校准。事件分数取所附来源初评分最低值，属于保守的证据摘要，不是贝叶斯聚合。仅采集器返回的来源最高 49 分，界面明确标注未独立直读。
- 每条卡片按共享 `us-equity-x-brief-quality` 技能整理：开头显示 X 作者；`fact` 是忠实翻译或概括后的中文信息摘要，不写“Grok 返回／原帖称”等采集过程；反向条件下方显示事件时间与主原帖链接。采集路径和独立直读缺口只留在证据详情。

## 每次定时执行

1. 在 `/Users/xswang/Documents/intelbrief-board` 读取 `CONTEXT.md`、本文件及 `config/research-guidance.json` 指向的项目知识库与采集 SOP，检查 git 状态，保留其他工作。项目内版本是采集时强制采用的当前快照；共享 `us-equity-x-intelligence`、`us-equity-multidisciplinary-knowledge` 和质量技能用于补充与复核，不能跳过项目 SOP。
2. 运行 `npm run brief:slot` 确定最近已到期时段。若该期 JSON 已存在，不覆盖。若仅部署未成功，重试该文件发布即可，不重采集。错过多个时段只制作最近一期，明确延迟和漏期，不伪造过去快照。
3. 信息截止固定为该时段整点。**展示窗口**固定为截止点往前完整 24 小时，期次卡片与页面展示必须覆盖该完整窗口（可用本期新检索结果加上本地已存的既有检索记录拼成）。**检索窗口**由执行器决定：可从最近一个有结果的**定时期次**截止时间起只检索未覆盖时段，避免重复检索；已检索时段须写入本地检索记录（每个时间段做过哪些检索）。手动测试与手动更新绝不能缩短、推进或替代定时窗口。没有上一期成功的定时简报、也没有可用本地记录时，默认检索截止前完整 24 小时。跨多日断档时本期展示仍须标明 24 小时窗口；未能补齐的空档写进 `coverage.gaps`。旧帖仅作标注的背景/延续；新进展至少一条窗口内原帖。即使采集晚到，整点后发布的帖子也留给下一期。
4. 严格遵守 [AGENTS.md的采集硬规则](../AGENTS.md)：先通过本机Grok Bot App的「X+github」Bot获取，失败时才用Grok网页版，除此之外全部禁止。旧「推特信息获取」及 App 内其他 Bot 不再用于本项目。两条都失败则报告失败，不改用X API、直访X或普通搜索。不得改动登录、发帖、私信、点赞、关注等；登录失效请用户处理，不从历史对话读取密码。
5. 依项目采集 SOP 用公开问题做广泛主题检索，再找原始来源、相反证据、时间与上下文。知识库只在执行上下文用于生成问题，不能把全文、个人资料或账户信息发送到 Grok。半导体、电力、AI 落地三个核心包以及宏观资本成本、地缘能源物流、市场结构行为三个跨学科包必须留下实际查询与覆盖记录；无合格结果可以不入选，不强行填配额。
6. 必须保留两个独立、可审计的检索阶段：第一轮宽扫并横向比较市场焦点；第二轮先把知识卡转成财政利率、AI 实物基础、地缘能源物流、市场结构与 AI 企业微观等公开问题，再重新检索、追源和寻找反证。不能把第一轮余下候选直接改名为多学科结果，也不能在没有执行第二轮时写 0 条。最后由当前模型完成 5+10 筛选及中文分析，保存两轮各自的检索问题、覆盖缺口与主要落选候选。互动量只描述可观察热度，不能证明事实或因果。记录相对上期的新增/进展/延续。
7. 用 `apply_patch` 在临时目录准备 JSON；执行 `npm run brief:validate -- FILE`，校验通过后 `npm run brief:publish -- FILE`。程序写入不可覆盖的 `data/stock-briefs/YYYY-MM-DD-HHMM.json` 并更新目录。不把测试夹具或私有材料放入线上数据。
8. 执行 `npm test` 与 `npm run check`，检查本期中文内容、条数、链接、时间、引用和因果边界。只暂存本期归档与目录的明确路径，提交并推送 `master`（沿用用户维护与发布授权）。发生分支冲突/其他用户改动时不强推、不重置，说明具体阻塞。确认线上对应归档能读取后才称已发布。
9. 一次采集故障最多两次有限重试；仍失败则发布失败记录并报告缺口，不无限等待。任务结束；下次由定时触发。正常报期次/条数与页面链接，失败报具体原因，不承诺已经稳定运行。

本地调度需要电脑与应用可用、Grok登录有效。页面能加载或任务创建成功不等于采集链已跑通；第一期实际采集仍需单独验证。通过Grok取得的材料须标为采集器转述，不得声称执行器独立直读原帖。

## JSON 输入

顶层必填：

| 字段 | 内容 |
|---|---|
| `scheduledFor` | 北京时间期次，如 `2026-10-11T21:00:00+08:00` |
| `windowStart` | 带时区的检索窗口起点 |
| `status` | `complete` 完整、`partial` 缺额、`failed` 失败 |
| `summary`, `marketContext` | 市场概览与交易时段/休市背景；保留在数据中供审计，不在期次选择区展示 |
| `coverage` | `{method:文字, queries:[实际查询], gaps:[缺口]}` |
| `selectionRationale` | 两组的比较及排序理由 |
| `excludedCandidates` | `[{eventKey:候选事件,reason:落选原因}]`，无则空数组 |
| `focus`, `insights` | 两组事件数组，完整时严格 5+10 |
| `shortfallReason` | 缺额/失败必填，完整可不填 |

每条事件必填 `eventKey`（同一事件跨期沿用稳定键）、`title`、`fact`（来源具体声称什么）、`impact`（独立判断）、`direction`（利多/利空/双向/待定）、`horizon`、`affected`（数组）、`counterCase`、`selectionReason`、`credibilityReason`、`change`（新增/进展/延续）、`sources`。`eventTime` 是带时区的真实事件时间；未知填 null 并填 `eventTimeNote`，预告未来事件加 `futureEventNote`。延续加 `continuationReason`，窗口前的背景来源加 `contextSourceNote`。

焦点另需 `attentionEvidence`。多学科另需 `knowledgeCards`（项目知识库 M01–M10、I01–I10、R01–R08 中的适用卡）、`disciplines`（至少两个不同学科）、`knowledgeApplication`（本期条件性传导与知识库适用边界）。项目知识库是经过整理的执行快照，不把共享 skill 全文、人物原始消息或私密资料复制进仓库。

每个来源必填 `url`（规范 X/Twitter status 链接）、`postId`（字符串）、`username`、`publishedAt`、`checkedAt`、`excerpt`（准确短摘录）、`verification`（`direct` 原帖直读 / `collector-report` 采集器转述）、`verificationNote`。全部日期含时区；核验时间真实记录，原文摘录避免长篇搬运。程序生成可信度，不接受手工虚构高分。

`id`、`schemaVersion`、`timezone`、`generatedAt`、`counts` 和可信度由发布程序生成。每一期归档不可覆盖；有错在后一期指出更正并引用原期次。失败期次 `focus:[]`、`insights:[]`，仍记录尝试方式与原因。
