# 北京时间批次与累计阅读

## 时间与展示

北京时间周一至周五08:00/20:00、周六08:00和周日20:00启动批次；实际开始采集的时间作为信息截止，计划期次和发布完成分别记录，不等待美国开盘或因美国节假日推迟。周一早报即可展示已收录周末消息。

[增量采集](INCREMENTAL_COLLECTION.md)维护搜索与恢复规则；逐对象接上次成功截止，手动与定时共享进度。24h/七天/30天是阅读范围，不驱动重复检索；周一汇总已入库周末存量，只查询余下增量。

首页默认“当前重点（累计保留）”。08:00的重要内容20:00仍可读；分清本轮新增、本轮有进展、累计保留与补充发现，原帖时间不改成收录时间。

- 持久池独立于最近三期快照，轮换快照不能删除仍有效卡片。
- 周六日事件归到周一阅读日，平日归到当日；旧内容在后续北京时间工作日08:00批次发布可用结果后按保留期转换状态，不以浏览器时钟静默清空。周末内容至少保留到周二08:00的后续可用发布。
- 日期归属是产品阅读日，不是交易所营业日，不由美国夏令时、银行假日或开收盘时间控制。
- 失败保留上一池。已展示不代表用户已读，没有个人已读追踪时不得作此推断。
- 5+10为重点上限；未入精选但仍有效的条目默认展开保留，不能因晚批有新增而删除早报重点。
- 人物、个股、AI以已发布截止判断有效旧内容，保留未冲突重点及`retainedItems`；失败Tab保留其最后成功数据和截止，不以网页当前时间自行清空。

## 同事件与更正

同事件沿用`eventKey`，实质进展合并到当前卡片并保留之前版本。无变化的复核不冒充新进展、不刷新原帖时间；长期续留必须有依据。更正、被替代、失效保存原卡、原因、来源及真实复核时间，不抹掉证据。

`readingSelection`为可选的`{focus:[eventKey…], insights:[eventKey…]}`，各最多5/10且组内唯一，引用当前有效池。没有显式排序时的机械后备顺序不能宣称是重要性比较。

`readingDecisions`为可选数组，字段`eventKey/action/reason/sourceUrl/checkedAt`，动作`keep/retracted/superseded/resolved`；须有真实带时区核验时间和来源依据。未核验不声称证伪，`keep`按北京时间阅读周期续留。

## 写入和证据

`scripts/lib/reading-period.js`计算阅读周期；`data/reading-board.json`保存完整卡片、首次收录、真实最近核验、阅读日、保留期限及修订。`brief:context`同时返回展示窗和逐对象采集窗，不能混用；采集进度以`data/collection-progress.json`为准。

内容发布按[简报契约](STOCK_BRIEF.md)更新归档、目录、持久池和真实采集审计，并核对线上资源。默认不运行本地测试/check/build或预览；来源核验和写入契约不因此取消。

原始帖子、事件时间、新闻归档与实际覆盖记录保留。交易所日历资料只用于适用的历史研究，不驱动此页收录；财报及宏观自身的官方时间规则不改变，也不扩大X来源权限。

程序边界包括午夜、跨年、周末归属、三期轮换、失败保留、同事件进展/撤回及补充发现；这些场景定义不等于本轮已运行测试，也不保证获准来源零漏收。
