# 美股交易日待阅：采集、展示和保留分离

采用：2026-10-12。用户主要在北京时间的美股开盘日阅读；休市期的重要消息必须保留到第一个实际开盘日，而非满24小时消失。本规则覆盖此前仅周一补扫的规则；本轮作用于美股讯息，不把美股休市日套到24/7加密页面。

## 当前规则

- 采集仍为北京时间每天09/16/21，不改变频率。按美国现金股票**常规交易时段**确定交易日，页面用北京时间说明，不能用中国工作日、美国银行假日或简单周一到周五代替交易所日历。
- **北京时间口径（用户2026-10-12再次确认）**：面向用户的开盘、收盘、更新、信息截止与保留期限统一使用Asia/Shanghai；待阅页直接列出北京时间的完整开盘日期时刻与收盘日期时刻，不以美东日期作阅读标签。一个时段按北京时间开盘日称呼，跨午夜仍属同一时段；内部交易所日历/归档键保留美东日期，不把中国自然日当作美股交易时段。更新的启动时间与实际发布完成时间必须分开说明，不能把21点启动说成21点已经出齐。
- 初次收录或有实质新事实的事件，归到收录时正在进行或接下来第一个常规交易时段，至少保留至该时段收市。周末、长假、盘后消息同理；北京时间过零点不换掉尚在进行的美股交易日。
- 每期展示回溯窗口取“过去24小时”和“目标交易日前一实际收市”中较早者；查询范围再纳入断档（最多自动回补14天，更早缺口明确说明）。`npm run brief:context -- CUTOFF` 返回准确窗口、下一/当前交易时段、未覆盖区间及待阅池，禁止凭记忆算周末。
- **最近三期快照不是信息寿命。** `data/reading-board.json` 独立持久保存完整卡片、首次收录、最近核验、对应交易日、保留期限和修订记录；发布程序先更新待阅池，再清理第四期快照。旧快照不可修改，原帖/事件时间不刷新成“今天”。
- 首次迁移只复制当前仍存在的真实归档，不追造此前已被清理的消息；这些更早信息需要Grok按缺口补查，不能用模型记忆恢复。
- 首页默认“交易日待阅”，精选仍最多5+10；Grok对跨期有效池重新排序。暂时未进入精选但仍有效的消息保留在默认展开的独立区域，不静默丢弃。没有提供显式排序时采用最近核验/原排序的机械后备顺序，不能宣称为重要性排名。
- 同一事件沿用eventKey，新进展合并，保留前版。无新增事实的重复评论不自动续期；仍需长期观察的事件必须有依据地复核后续留。已证伪、被替代、失效时记录原因、原帖依据与复核时间，退出精选但不抹掉历史。
- 成功的后续发布才把已结束交易时段的旧卡转为已展示状态，**不代表用户已读**。采集失败不清空待阅池；网页本身不因本地时间过去而删除卡片，只提示其对应时段已结束、等待更新。
- 日历超出核验范围或临时调整无证据时，不猜下个开盘日、不自动清空待阅；显示日历待核验。按官方消息维护临时停市/更改开闭市时间，下一次发布重新计算保留期。盘中熔断不是完整休市日；目前不接实时交易所状态流，未确认的临时停市不能冒充已识别。

## 日历证据与维护

`config/us-market-calendar.json` 保存2026–2028年官方节假日、提前收市、核验日期、有效范围与覆盖调整。常规时段09:30–16:00美东；通过`America/New_York`时区转换夏令时，不固定加12/13小时。2027-12-31没有因2028元旦周六而补休，银行假日也不自动关闭股票市场。

来源：[NYSE交易时段与日历](https://www.nyse.com/trade/hours-calendars)、[ICE 2026–2028公告](https://ir.theice.com/press/news-details/2025/NYSE-Group-Announces-2026-2027-and-2028-Holiday-and-Early-Closings-Calendar/default.aspx)，2026-10-12核对。日历是本项目的官方元数据例外，不构成扩大X讯息采集来源的许可。Grok运营时发现官方更正可按既有权限维护配置；季度/跨年接手核对覆盖范围，不另建频率。

临时调整放`overrides[美东日期]`，必须有`source`（官方URL）、`reason`，及`closed:true`或`open/close`（美东HH:mm）。未知就保留并报告，不能拿预测的周一填日期。

## Grok每期执行与字段

1. 拉取最新master，读AGENTS/STOCK_BRIEF/本文/SOP，再运行`brief:context`。检查池内前期事件的实质新增、反证与有效性，不仅搜索本期新帖。
2. 输出v2简报时，`displayWindowStart/End`用上下文的`start/end`，`windowStart`用`searchWindowStart`；只跳过有明确成功覆盖记录的查询区间。失败、部分结果、没有状态的旧记录都不算已完整检查，不能因此停止补查。除时间外还要检查六个主题包；一个主题成功不能当作全包覆盖。
3. `readingSelection`可选：`{focus:[eventKey…],insights:[eventKey…]}`，各最多5/10、组内唯一、引用当前有效池；包含本期和前期真正重要事件。未入精选不等于退出保留池。
4. `readingDecisions`可选：`[{eventKey,action,reason,sourceUrl,checkedAt}]`。action为`keep/retracted/superseded/resolved`；必须有明确原因、有效X原帖依据、真实带时区复核时间。`keep`延至当前/下一交易时段收市；其余退出有效池并留痕。未复核不得假称已经证伪或失效。
5. 按原契约校验发布；`brief:publish`自动更新`data/reading-board.json`和`data/search-coverage.json`，同次提交归档、目录、待阅池、真实检索覆盖记录及必要财报数据。简报的`coverage.status`只有确实完整成功的区间才填`complete`；程序还要求有查询、无缺口且检索前清单全部为已覆盖或确实无结果，否则记为部分覆盖。不要因为精选不足15条就认定采集失败，也不要因足15条就假称检索完整。手动、失败、部分及无状态的历史记录不推进定时检索覆盖。
6. 测试、数据校验、构建、提交推送；核对线上本期归档、目录和`data/reading-board.json`，不是只确认网页HTTP成功。未部署重试发布核验，不重新采集或修改冻结期次。

## 回归场景

普通隔夜、周末、长周末、Good Friday、感恩节/圣诞提前收市、跨年和夏令时；临时休市修订；超过三期仍保留；晚发现消息不伪装新发生；同事件更新/撤回；信息过多时的分区保留（默认展开）；重复发布幂等；失败不清空；未知日历不删；不把手动采集或不完整检索冒充完整覆盖。

这些测试验证程序边界，不保证获准来源永不漏讯息；权限、限流、采集缺口和日历时效仍必须透明报告。
